# Bitácora de Aprendizaje: Reto 00 - Configuración e Inicialización de Git y GitHub

### 1. 🎯 Lo que dominé hoy (El clic mental)
* Comprendí la arquitectura de control de versiones: **Git** registra el historial local mediante estados ("fotografías" del código) y **GitHub** actúa como el respaldo centralizado en la nube para sincronizar proyectos entre diferentes equipos.
* Aprendí la secuencia fundamental de trabajo en terminal: `git add .` (preparar cambios en Staging Area), `git commit` (registrar la versión) y `git push` (subir cambios al repositorio remoto).

### 2. ⚠️ Tropezones, errores y cómo los solucioné
1. **Rechazo de autenticación por contraseña tradicional al hacer `git push`:**
   * *Error:* `remote: Invalid username or token. Password authentication is not supported`.
   * *Por qué pasó:* GitHub eliminó el soporte para contraseñas planas en la terminal por motivos de seguridad.
   * *Solución:* Generar un *Personal Access Token* (PAT) en GitHub con permisos de `repo` y usar el token como clave en la terminal.
2. **Terminal bloqueada al inspeccionar el historial con `git log`:**
   * *Por qué pasó:* `git log` utiliza el visor de texto interno `less` para navegar por historiales largos.
   * *Solución:* Presionar la tecla `q` (*Quit*) para cerrar la vista y recuperar el control de la terminal.
3. **Advertencia de nombre de rama por defecto en `git init`:**
   * *Error/Hint:* Advertencia recomendando estandarizar el nombre de la rama principal a `main` en lugar de `master`.
   * *Solución:* Configurar el estándar globalmente con `git config --global init.defaultBranch main` y renombrar la rama actual con `git branch -m main`.
